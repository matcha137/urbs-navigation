## 空間結合の歩留まり（T-12 の判断根拠）

公園にバリアフリー属性が無いため、公衆トイレ・公共施設の座標と距離で結合して属性を導出する。
`etl/01c-joincheck.mjs` の実測：

| 結合半径 | トイレあり | うち車椅子対応 | 屋内BF施設あり |
|---|---|---|---|
| 100m | 128 / 173 (74%) | 108 (62%) | 30 |
| 150m | 142 / 173 (82%) | 123 (71%) | 57 |
| **200m** | **151 / 173 (87%)** | **135 (78%)** | **82** |
| 300m | 162 / 173 (94%) | 159 (92%) | 133 |

**採用半径は 200m。** 最も厳しい `achy`（車椅子対応トイレ必須）でも **135件**の候補が残るため、
体調によるハードフィルタが機能する。150m だと 123 件、100m でも 108 件あるので余裕がある。

## 見送り（候補には挙げたが不採用）

| データセット | 理由 |
|---|---|
| 文京区 都市公園・都立公園一覧 (119件) | 座標100%だが**バリアフリー属性が皆無**。文京区には公衆トイレのオープンデータが存在しない |
| 文京区 区立公園・児童遊園・遊び場一覧 (119件) | 「説明（日本語）」列が使えて魅力的だが、同上の理由でバリアフリー結合ができない |
| 文京区 区内の公園 | ZIP（GIS形式）。展開と変換のコストに見合わない |
| 江東区 スポーツ施設一覧 (88件) | **緯度経度の有効率が22%**。使い物にならない |
| 江東区 観光施設一覧 (25件) | バリアフリー列が全て空。件数も少ない |
| 東京都建設局・都市整備局・環境局 | 「都市計画公園・緑地の整備方針」等の**政策文書PDF/CSV**が大半で、点データではない |

### なぜ文京区を外したか

design/ のモックはステータスバーに「Bunkyo」と書かれているが、
登場する場所（清澄庭園・深川・小名木川）は**すべて江東区**。
かつバリアフリーのオープンデータが揃っているのも江東区のみだったため、
デモ舞台を江東区に一本化した。モックの世界観とはむしろ整合する。

## データに存在しなかったもの（要仕様変更）

| モック/T-06 が前提にしていたもの | 実データ | 対応 |
|---|---|---|
| **ベンチの数**（「80mごとにベンチ」「座れる場所3つ」） | **どのデータセットにも存在しない** | `place_access.bench_count` の供給元が無い。T-06 の `minBenchCount` は現状のままだと全件を落とす |
| 段差の有無（公園内） | 公園データに無い。公共施設の「スロープ、エレベータ、エスカレータ」のみ（充足17%） | 公園は「未知」として扱い、施設のみ `step_free` を宣言値で持つ |
| 手すり | 存在しない | `handrail` は常に0。UIから外すか、施設限定で表示 |
| 最寄バス停までの距離 | 今回の3データセットには無い | `nearest_transit_m` は NULL のまま。T-06 の `maxTransitWalkM` は当面フィルタに使えない |

**面積(㎡) は全件にある**ので、ベンチ数の代替指標として使える可能性がある（広い公園ほど座る場所がある）。
ただしこれは推定であり、`place_access.confidence='inferred'` として明示すること。
