## 空間結合の歩留まり（T-12 の判断根拠）

公園にバリアフリー属性が無いため、公衆トイレ・公共施設の座標と距離で結合して属性を導出する。
`etl/01c-joincheck.mjs` の実測：

| 結合半径 | トイレあり | うち車椅子対応 | 屋内BF施設あり |
|---|---|---|---|
| 100m | 128 / 173 (74%) | 108 (62%) | 30 |
| 150m | 142 / 173 (82%) | 123 (71%) | 57 |
| **200m** | **151 / 173 (87%)** | **135 (78%)** | **82** |
| 300m | 162 / 173 (94%) | 159 (92%) | 133 |

**採用半径は 200m。** 最も厳しい `achy`（車椅子対応トイレ必須）でも **135件**の候補が残るため、
体調によるハードフィルタが機能する。150m だと 123 件、100m でも 108 件あるので余裕がある。

## 見送り（候補には挙げたが不採用）

| データセット | 理由 |
|---|---|
| 文京区 都市公園・都立公園一覧 (119件) | 座標100%だが**バリアフリー属性が皆無**。文京区には公衆トイレのオープンデータが存在しない |
| 文京区 区立公園・児童遊園・遊び場一覧 (119件) | 「説明（日本語）」列が使えて魅力的だが、同上の理由でバリアフリー結合ができない |
| 文京区 区内の公園 | ZIP（GIS形式）。展開と変換のコストに見合わない |
| 江東区 スポーツ施設一覧 (88件) | **緯度経度の有効率が22%**。使い物にならない |
| 江東区 観光施設一覧 (25件) | バリアフリー列が全て空。件数も少ない |
| 東京都建設局・都市整備局・環境局 | 「都市計画公園・緑地の整備方針」等の**政策文書PDF/CSV**が大半で、点データではない |

### なぜ文京区を外したか

design/ のモックはステータスバーに「Bunkyo」と書かれているが、
登場する場所（清澄庭園・深川・小名木川）は**すべて江東区**。
かつバリアフリーのオープンデータが揃っているのも江東区のみだったため、
デモ舞台を江東区に一本化した。モックの世界観とはむしろ整合する。

| モック/T-06 が前提にしていたもの | 実データ | 対応 |
|---|---|---|
| **ベンチの数**（「80mごとにベンチ」「座れる場所3つ」） | **どのデータセットにも存在しない** | `place_access.bench_count` の供給元が無い。T-06 の `minBenchCount` は現状のままだと全件を落とす |
| 段差の有無（公園内） | 公園データに無い。公共施設の「スロープ、エレベータ、エスカレータ」のみ（充足17%） | 公園は「未知」として扱い、施設のみ `step_free` を宣言値で持つ |
| 手すり | 存在しない | `handrail` は常に0。UIから外すか、施設限定で表示 |
| 最寄バス停までの距離 | 今回の3データセットには無い | `nearest_transit_m` は NULL のまま。T-06 の `maxTransitWalkM` は当面フィルタに使えない |

### 対応（確定・実装済み）

**方針1+2の併用を採用した。**

1. **面積(㎡) を「座れる場所」の代替指標にする** — 173件すべてに入っている。
   閾値は実分布に合わせて `config/feels.ts` の `SEATING_AREA_TIERS` に定義:
   `≥10,000㎡ → tier3 (20件) / ≥3,000㎡ → tier2 (47件) / ≥1,000㎡ → tier1 (128件)`
   実分布: min 114㎡ / p25 986㎡ / 中央値 1,690㎡ / p75 3,150㎡ / p90 12,691㎡ / max 152,998㎡
2. **ベンチをハードフィルタから外した** — `minBenchCount` を削除し、
   `preferredSeatingTier` としてスコア加点に降格。下回っても候補から落とさない。

あわせて、同じ「データが無いのに必須条件にしていた」問題を2件修正した:

- `maxTransitWalkM` (最寄バス停) → データが無いためフィルタから削除。`DATA_GAPS` に記録
- `requireStepFree` → `excludeKnownStepped` に変更。
  **「段差ありと明記された場所だけを除外」** する意味に変えた。
  段差データを持たない公園を「非対応」として全滅させないため、
  `place_access.step_free` は三値 (1/0/NULL) にしてある。

### 改訂後のフィルタ通過数（起点: 清澄白河駅 / `etl/01d-filtercheck.mjs`）

母集団は公園173 + 公共施設617 = 790件（重複未除去）。

| feel | 距離内 | 段差除外後 | だれでもトイレ必須後 | 最終候補 |
|---|---|---|---|---|
| good | 97 | 97 | 97 | **97** |
| tired | 34 | 33 | 33 | **33** |
| achy | 15 | 15 | 12 | **12** |
| low | 3 | 3 | 3 | **3** |

### 判明した追加課題

**公園が2つのデータセットに重複して存在する。**
「江東区立清澄二丁目公園」「江東区立白河一丁目公園」は
都市公園一覧と公共施設一覧の両方に載っている。
T-16 の名寄せで、名称と座標（半径50m程度）による重複排除が必須。

`etl/mappings/` に3ファイル。`role` で place（母集団）と donor（属性の供給元）を分けている。
公衆トイレは**行き先ではなく属性の供給元**なので `role: 'donor'`、places には入らない。

公共施設一覧では **632件のうち228件を除外**した。学校・きっずクラブ・防災倉庫・区営住宅・
駐車場など「外出先として選ばない施設」を大区分と小区分のキーワードで落としている。

### T-16 正規化・名寄せ・空間結合

| 段階 | 件数 |
|---|---|
| マッピング適用後 | 577（公園173 + 施設404） |
| **名寄せ後** | **409**（168件を統合） |

**統合時は両方のデータセットを出典として残す。** 結果、409件のうち

### 検査で残っている警告

`scripts/check-normalized.mjs` はエラー0件。ただし「30m以内にある別名の場所」の警告が43件ある。
大半は**公園とその隣の地区集会所**で、別物として正しく残っている（集会所は雨天時の屋内退避先になる）。
1件だけ「潮見さざなみ公園 / 潮見しぶさわ公園」が座標0mで、元データ側の座標入力ミスと思われる。

バリアフリーが宣言値で屋内なので `achy` の休憩先としては妥当だが、
「行きたい場所」として提示されると不自然。スコアリング (T-32) で
category や小区分による減点を入れるか、除外リストに足すかは要判断。

## 投入（T-19〜T-21）

パイプライン全体: `npm run etl` → `npm run db:seed`

```
etl:encode → etl:normalize → check:normalized → etl:select → etl:emit → db:seed
```

### T-19 絞り込み — 間引きは行わなかった

計画では「200件に間引く」としていたが、実データを見て**かけないことにした**。

- bbox フィルタ（江東区の外接矩形）で落ちた件数は **0**。座標の入力ミスは無かった
  （実測範囲 lat 35.620〜35.707 / lng 139.779〜139.847）
- デモ起点からの到達件数が既に薄く、間引きは**薄い方をさらに薄くする方向にしか働かない**

| プロファイル | 距離上限 | 到達件数 |
|---|---|---|
| low | 250m | **2** |
| achy | 450m | 10 |
| tired | 600m | 20 |
| good | 1200m | 56 |

409件は D1 にとって全く負荷にならない規模（DB サイズ 0.57MB）であり、
区全域を持っておくと「別の場所を見せて」と自然文検索の母集団が確保できる。
必要になったときのために `node etl/04-select.mjs --limit=200` は残してある。

**要注意: `low` の到達が2件しかない。** `maxStops=1` なので本命1件＋代替1件で成立はするが、
起点が変わると 0 件になりうる。`config/feels.ts` の `low.maxDistanceM` を
250m → 350m に緩める判断が要る（350m なら実測で候補が増える）。

### D1 の落とし穴: `power()` が使えない

距離計算を SQL 側でやろうとすると引っかかる。

```
power(x, 2) → not authorized to use function: power (SQLITE_ERROR 7500)
```

`sin` / `cos` / `sqrt` / `asin` / `radians` / `abs` は使えるので、
二乗は `x * x` と書けば通る。動作確認済みのクエリを `db/queries.sql` に置いた。
**T-31（距離計算）と T-32（ハードフィルタ）はそれを写して実装すること。**

三値カラムの条件も同じファイルに書いてある。`step_free = 1` ではなく
`(step_free IS NULL OR step_free = 1)` と書かないと、段差データを持たない公園が全滅する。
